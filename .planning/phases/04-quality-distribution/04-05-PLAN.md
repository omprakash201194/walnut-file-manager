Create `.github/workflows/release.yml` with this exact content:

```yaml
name: Release

on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    name: Build & Release (Windows)
    runs-on: windows-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build Windows installer
        run: npm run build:win
        env:
          GH_TOKEN: ${{ secrets.GH_TOKEN }}

      - name: Upload release artifacts
        uses: actions/upload-artifact@v4
        with:
          name: windows-installer
          path: dist/*.exe
          if-no-files-found: error
```

Notes:
- `on.push.tags: v*` triggers on semver tags like v1.0.0 (D-08)
- `GH_TOKEN` secret must be set in GitHub repository settings → Secrets → Actions. The release workflow passes it to electron-builder so it can publish the installer to GitHub Releases via `--publish onTag` (which is triggered by the publish.provider=github config in electron-builder.yml).
- `npm run build:win` calls `npm run build && electron-builder --win` — the `electron-builder` step picks up `GH_TOKEN` from env to upload to the GitHub Release matching the tag.
- `actions/upload-artifact@v4` with `dist/*.exe` uploads the NSIS installer as a workflow artifact as a fallback. The primary release mechanism is electron-builder's GitHub publisher.
- `if-no-files-found: error` fails the job if no .exe was produced, catching build failures early.
- The installer will be named `walnut-1.0.0-setup.exe` per the `${name}-${version}-setup.${ext}` template with `name=walnut` (fixed in Plan 01).
